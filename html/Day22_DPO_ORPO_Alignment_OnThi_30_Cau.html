AICB • Day 22 • Track 3

DPO, ORPO & Alignment

Ôn thi bám slide với 30 câu trắc nghiệm đáp án nhiễu gần nhau và A/B/C/D random cân bằng.

📚 Kiến thức trọng tâm

Ý lớn nhất Day 22

SFT dạy format/instruction following; Alignment dạy model phân biệt câu trả lời tốt/xấu: helpful, harmless, honest. Preference data học được margin giữa good và bad.

🎯 NHỚ ĐỂ THI
SFT = nói gì/format. DPO/ORPO = nói như thế nào tốt hơn.
01 • SFT vs Alignment

Tại sao SFT chưa đủ?

SFT-only có thể verbose, generic, refusal quá mức. Alignment dùng preference data để hướng output direct, concise, actionable và safety cân bằng.

🎯 NHỚ ĐỂ THI
Alignment không dùng để thêm knowledge mới.
02 • RLHF

3-stage pipeline

SFT→Reward Model→PPO

RLHF tốt nhưng nhiều models/stages, PPO nhạy hyperparameter và có reward hacking.

🎯 NHỚ ĐỂ THI
RLHF = SFT → RM → PPO.
03 • DPO

Direct Preference Optimization

DPO train trực tiếp trên prompt + chosen + rejected; không cần Reward Model trực tiếp trong DPO loss. Dùng policy model + reference model, offline, không rollout.

🎯 NHỚ ĐỂ THI
DPO = học trực tiếp pair tốt/xấu.
03 • Beta

Mức KL constraint

β=0.1 là default trong slide. β cao → model gần reference hơn; β thấp → tự do optimize preference hơn. Quá conservative → giảm β; quên kiến thức → tăng β.

🎯 NHỚ ĐỂ THI
β↑ → gần ref. β↓ → tự do hơn.
03 • Failure Modes

DPO có thể train xong nhưng tệ

Likelihood displacement, length hacking, mode collapse/sycophancy. Warning: rewards/chosen giảm, margin xấu, length tăng mạnh.

🎯 NHỚ ĐỂ THI
Chosen reward đảo chiều → cân nhắc stop.
04 • Chọn Method

Quick rules

Điều kiệnMethod
Có SFT + preference pairsDPO
No SFT, Base→Aligned 1 stageORPO
VRAM hạn chế + length biasSimPO
Chỉ thumbs up/downKTO
Math/code có ground truthGRPO + RLVR
🎯 NHỚ ĐỂ THI
DPO vẫn là baseline chính; đổi method khi có lý do cụ thể.
04 • ORPO

Single-stage alignment

ORPO gộp SFT loss + preference loss trong một objective; không cần ref model; có thể Base → aligned trong một run.

🎯 NHỚ ĐỂ THI
ORPO = 1 stage, no ref.
04 • SimPO & KTO

Alternative sau DPO

SimPO: reference-free, length-normalized. KTO: mỗi example chỉ cần good/bad (+1/-1), phù hợp feedback production.

🎯 NHỚ ĐỂ THI
SimPO = no ref + length norm. KTO = single signal.
05 • GRPO

PPO không value model

GRPO sinh nhóm outputs cho cùng prompt, dùng group mean reward làm baseline thay value/critic model.

🎯 NHỚ ĐỂ THI
GRPO = group-relative baseline.
05 • RLVR

Verifiable Rewards

Reward được check bằng code: math answer match, unit test, regex/JSON schema, tool success/error. Không thay preference learning cho subjective tasks.

🎯 NHỚ ĐỂ THI
Check programmatically → RLVR. Human judgment → DPO.
06 • Preference Data

prompt + chosen + rejected

Pair phải khác biệt genuine, không chỉ khác length. Healthy DPO: chosen reward tăng, rejected giảm, gap widen.

🎯 NHỚ ĐỂ THI
Chosen ↑ • Rejected ↓ • Gap ↑.
06 • Iterative DPO

One-shot không đủ

Modern recipes lặp generate → select best/worst → SFT/DPO với data mới. Tulu 3: SFT → DPO → RLVR.

🎯 NHỚ ĐỂ THI
DPO production thường iterative.
07 • Constitutional AI

Self-improvement

Generate→Critique→Revise→Preference Pair

Dùng constitution về helpfulness, harmlessness, honesty để model tự critique/revise rồi tạo preference data.

🎯 NHỚ ĐỂ THI
CAI = tự critique → tự sửa → tạo pair.
07 • Red Teaming

Safety loop

Probe harmful outputs → analyze failures → feed findings vào preference data → retrain/update. Slide nêu Garak và PyRIT.

🎯 NHỚ ĐỂ THI
Red-team phải feed failure trở lại data.
08 • Evaluation

Đo nhiều góc

Static: MMLU/GSM8K/MATH/IFEval/HumanEval/TruthfulQA. Judge-based: MT-Bench, AlpacaEval 2 LC, Arena-Hard, Chatbot Arena. RewardBench đánh giá judge/reward model.

🎯 NHỚ ĐỂ THI
Không benchmark nào đủ một mình.
09 • Lab 22

DPO trên SFT checkpoint

Prepare pairs → DPOTrainer → monitor rewards → compare SFT-only vs SFT+DPO → merge/deploy. Bonus DPO vs ORPO và preference data tiếng Việt.

🎯 NHỚ ĐỂ THI
Pair data → DPO → Compare → Deploy.
10 • Full Flow

Modern post-training stack

Đa số team thực tế tập trung ở post-training: SFT → DPO → RLVR → merge/distill/optimize. Enterprise thường SFT + DPO là đủ; RLVR thêm khi reasoning có ground truth.

🎯 NHỚ ĐỂ THI
SFT + DPO = core stack; RLVR thêm khi cần.

Multi-Agent & Kết Nối Hệ Thống

MCP · A2A · LangGraph · Supervisor–Worker · Ôn thi nhanh
⚡ TÓM GỌN TOÀN BÀI

Đọc đoạn này trước khi thi

Day 09 = chia một “god agent” thành một hệ thống có vai trò rõ. Chỉ nghĩ tới Multi-Agent (nhiều agent phối hợp) khi single-agent gặp context bottleneck (nút thắt ngữ cảnh), cần specialization (chuyên môn hóa), parallelism (song song), hoặc cần failure isolation (cô lập lỗi). Pattern trọng tâm là Supervisor–Worker: Supervisor giữ decision flow (luồng quyết định), route và tổng hợp; Worker giữ domain skill (năng lực chuyên môn), nên hẹp, stateless và testable. Shared State giúp điều phối; Message Contract giúp agents giao tiếp không mơ hồ. MCP là chuẩn agent ↔ tool/capability, còn A2A là agent ↔ agent. LangGraph biểu diễn orchestration bằng Node = ai làm, Edge = đi đâu, State = hệ biết gì, cộng conditional routing. Cuối cùng, Observability/Trace là bắt buộc để biết ai làm gì, khi nào, mất bao lâu, lỗi ở đâu và dùng dữ liệu đó cải thiện hệ thống.

01 · Single-Agent → Multi-Agent

Khi một agent phải ôm quá nhiều vai trò

Context bottleneck (nút thắt ngữ cảnh): Một agent phải giữ goals, tool outputs, evidence và state trong cùng context; dễ lost-in-the-middle.

Specialization trade-off (đánh đổi chuyên môn hóa): Prompt càng ôm nhiều vai càng dài và khó ổn định; giỏi đều thường thành không thật sự giỏi vai nào.

Parallelism (khả năng chạy song song): Single-agent thường tuần tự; nhiều việc độc lập vẫn phải chờ nhau nên tăng latency.

Reliability (độ tin cậy): Sai tool hoặc hiểu sai task đầu luồng có thể kéo lệch cả hệ; thiếu isolation để khoanh vùng lỗi.

When multi-agent? (khi nào nên dùng multi-agent): Task nhiều vai, có phần độc lập chạy song song, cần debug rõ, cần thêm worker dần, hoặc context một agent không đủ. Không dùng chỉ vì “ngầu”.

02 · Mental Model

Từ “agent thông minh” sang “hệ thống rõ ràng”

God agent (agent làm tất cả): Anti-goal: một agent ôm mọi tool và trách nhiệm khiến khó hiểu, khó test, khó debug.

Responsibility split (chia trách nhiệm): Hỏi task nào cần reasoning, data fetching, formatting; ai cần biết gì và khi nào.

Failure isolation (cô lập lỗi): Thiết kế để worker lỗi không làm hỏng toàn hệ thống; lỗi phải có “địa chỉ”.

Human oversight (giám sát của con người): Xác định trước điểm nào cần con người kiểm tra/quyết định.

03 · 4 Multi-Agent Patterns

Chọn pattern theo loại phức tạp

Supervisor-worker (một supervisor điều phối nhiều worker chuyên biệt): Mạnh: routing rõ, dễ control/trace. Cảnh báo: supervisor có thể thành bottleneck.

Pipeline (chuỗi agent tuyến tính): A xong → B → C. Hợp flow cố định, dễ test; yếu khi cần rẽ nhánh, latency cộng dồn.

Debate (nhiều agent cùng giải rồi vote/synthesize): Hợp bài toán nhiều góc nhìn/rủi ro cao; giảm blind spot nhưng tốn cost và khó tổng hợp.

Hierarchical (nhiều tầng supervisor): Hợp nhiều nhóm task/quy mô lớn; scale tốt nhưng thiết kế/debug phức tạp.

04 · Supervisor–Worker

Pattern trọng tâm của Day 09

Supervisor (agent điều phối): Phân tích request, chọn worker, theo dõi state/retry, tổng hợp cuối, biết khi nào cần human review.

Worker (agent chuyên một năng lực hẹp): Input/output rõ, càng stateless càng dễ test, lỗi cục bộ, có thể thay thế độc lập.

Architecture (kiến trúc): User Request → Supervisor → Retrieval/Tool/Synthesis Workers → Final Answer + Trace.

Anti-patterns (mẫu thiết kế xấu): God Supervisor, Chatty Workers, Implicit State, No Fallback.

05 · State & Message Contract

Điều phối rõ và giao tiếp không nhập nhằng

Shared state (trạng thái dùng chung): Dễ nhìn toàn cảnh và hợp graph orchestration; cần schema/ownership rõ để tránh agents ghi đè lẫn nhau.

Message passing (truyền thông điệp): Coupling thấp, contract rõ; cần format và validation tại điểm nhận.

State schema (lược đồ trạng thái): Tối thiểu: task, plan, worker_results, status, final_answer, trace. Lab còn có user_context, retrieval_result, tool_result, synthesis_draft, error.

Message contract (hợp đồng thông điệp): Nêu task, context/constraints và expected_output. Ví dụ retrieve evidence → top 3 chunks + source + confidence.

06 · MCP

Model Context Protocol – chuẩn nối agent với capability bên ngoài

MCP (Model Context Protocol): Giống “ổ cắm USB”: agent/client nói chuyện với MCP server thay vì custom adapter cho từng tool.

MCP surface (bề mặt khả năng server công bố): Server có thể expose tools, resources, prompts; agent list/describe/invoke theo chuẩn chung.

Tool discovery (khám phá tool): Connect → tools/list → nhận name/description/inputSchema → chọn tool → tools/call → server trả kết quả.

Why MCP? (vì sao cần MCP): Giảm hard-code tích hợp; tool/API thay đổi có thể xử lý ở server, worker không cần biết hệ thống phía sau.

07 · A2A

Agent-to-Agent – agent giao việc cho agent

A2A (Agent-to-Agent communication): Dùng để chia việc/đồng bộ giữa agents; agent nhận việc có agency và có thể ra quyết định.

MCP vs A2A (phân biệt cực quan trọng): MCP = agent ↔ tool/capability; A2A = agent ↔ agent. MCP hỏi “lấy năng lực ở đâu?”, A2A hỏi “giao việc cho ai?”.

Contract (hợp đồng giao tiếp): Task phải rõ, context đủ, expected output có format để supervisor biết dùng kết quả thế nào.

08 · LangGraph

Orchestration bằng graph

Node (nút – ai làm): Mỗi node đại diện một bước/agent/function.

Edge (cạnh – đi đâu tiếp): Kết nối các node; conditional edge chọn đường đi theo state.

State (trạng thái – hệ đang biết gì): Dữ liệu đi xuyên graph; có thể persistence để lưu và tiếp tục.

Conditional routing (định tuyến có điều kiện): Làm lộ rõ quyết định route, dễ debug và visualize.

Human-in-the-loop (con người trong vòng lặp): Thêm human_review node, interrupt graph, giữ state, sau approve tiếp tục và ghi quyết định vào trace.

09 · Observability & Reliability

Không có trace thì multi-agent rất khó debug

Observability (khả năng quan sát hệ thống): Biết agent nào làm gì, route nào được chọn, lỗi/latency ở đâu.

Trace (nhật ký luồng): Entry nên có timestamp, agent_id, action, input_summary, output_summary, status, latency_ms.

Retry / Timeout / Fallback (thử lại / giới hạn thời gian / phương án dự phòng): Worker phải timeout rõ; retry có giới hạn; fail tiếp thì fallback. Partial failure vẫn có thể tổng hợp phần thành công.

Graceful degradation (suy giảm có kiểm soát): Không cần luôn hoàn hảo; cần thất bại có kiểm soát và báo rõ khi không đủ tự tin.

Cost trade-off (đánh đổi chi phí): Nhiều agent = nhiều LLM call; retry tăng cost. Supervisor routing đơn giản không nhất thiết cần model lớn nhất.

10 · Lab 9

Nâng Day 08 RAG thành hệ multi-agent nhỏ

Deliverable (sản phẩm cần nộp): 1 supervisor + 2–3 workers + 1 MCP-connected capability + shared state có trace + output cuối có source.

Worker roles (vai trò worker): Ví dụ Retrieval Worker, Tool Worker, Synthesis Worker.

Evidence (bằng chứng cần demo): Trace/log đọc được, route hợp lý và lý do, ít nhất 1 worker fail gracefully.

Rubric (tiêu chí chấm): Vai trò rõ, MCP discovery/error handling, state ownership, trace actionable, conditional routing giải thích được.

🧠 30 câu trắc nghiệm

Chọn đáp án → hiện đúng/sai ngay. Đáp án A/B/C/D đã được phân bố.

✍️ 10 câu tự luận trọng tâm

Câu 1. Nêu 4 giới hạn cốt lõi của single-agent.
Context bottleneck; specialization trade-off; parallelism hạn chế; reliability yếu do lỗi dễ lan toàn luồng.
Câu 2. So sánh 4 multi-agent patterns.
Supervisor-worker: route theo vai; Pipeline: tuyến tính cố định; Debate: nhiều góc nhìn rồi tổng hợp; Hierarchical: nhiều tầng supervisor cho quy mô lớn.
Câu 3. Supervisor và Worker khác nhau thế nào?
Supervisor giữ decision flow: phân tích, route, state/retry, tổng hợp, human review. Worker giữ domain skill hẹp, input/output rõ, stateless/testable.
Câu 4. Shared State và Message Passing khác nhau thế nào?
Shared state thuận tiện điều phối/toàn cảnh nhưng cần ownership; message passing ít coupling và contract rõ nhưng phải format/validate kỹ.
Câu 5. Giải thích MCP bằng ví dụ dễ nhớ.
MCP giống ổ cắm USB chuẩn giữa agent và external capability. MCP server expose tools/resources/prompts; agent khám phá rồi invoke theo schema chung.
Câu 6. Phân biệt MCP và A2A.
MCP = agent nói với tool/capability; A2A = agent giao việc cho agent khác. MCP tập trung surface chuẩn; A2A tập trung message contract.
Câu 7. Giải thích Node, Edge, State trong LangGraph.
Node = ai/bước nào làm; Edge = đi đâu tiếp; State = hệ đang biết gì. Conditional edge route dựa trên state.
Câu 8. Trace tốt cần những trường nào?
timestamp, agent_id, action, input_summary, output_summary, status, latency_ms; có thể thêm decision/reason để route actionable.
Câu 9. Thiết kế reliability khi worker fail.
Timeout rõ → retry giới hạn → fallback; cho partial failure, tổng hợp worker thành công; graceful degradation và báo rõ uncertainty.
Câu 10. Mô tả Lab 9 cần nộp.
Nâng Day08 thành 1 supervisor + 2–3 workers, shared state có trace, 1 worker dùng MCP, message contract, conditional routing, output có source và ví dụ fail gracefully.

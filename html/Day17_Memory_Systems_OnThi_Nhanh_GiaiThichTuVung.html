AICB • Day 17 • Track 3

Memory Systems for Agents

Web ôn thi nhanh theo đúng slide Day 17: hiểu vì sao agent “quên”, phân biệt 4 loại memory, thiết kế context/memory flow, privacy và các xu hướng memory 2025–2026.

📚 Bản đồ kiến thức trọng tâm

Ý lớn nhất của bài

LLM mặc định không có persistent state (trạng thái được lưu bền vững qua các phiên). Context window (cửa sổ ngữ cảnh – phần thông tin LLM đang nhìn thấy) chỉ là bộ nhớ làm việc tạm thời; muốn agent nhớ qua session phải có external store (kho lưu trữ bên ngoài để nhớ lâu dài) và cơ chế retrieve (truy hồi/lấy lại thông tin) → inject (đưa thông tin vào context cho LLM) → write-back (ghi thông tin mới trở lại bộ nhớ). Memory tốt không phải “lưu càng nhiều càng tốt”, mà là lưu đúng loại, truy hồi đúng lúc, trim đúng budget và bảo vệ privacy từ đầu.

01 • Vì sao Agent quên?

Stateless by default

Mỗi API call độc lập; session mới không tự mang state của session cũ. Conversation dài cũng sẽ chạm giới hạn context.

Context Window (cửa sổ ngữ cảnh – phần thông tin LLM đang nhìn thấy) ≈ RAMNhanh, tạm thời, giới hạn dung lượng (~128K token trong ví dụ slide).
External Store (kho lưu trữ bên ngoài để nhớ lâu dài) ≈ ổ cứngChậm hơn nhưng bền vững, dùng Redis / Vector DB (cơ sở dữ liệu vector để tìm kiếm tương đồng).

Agent production cần cả hai: fast access cho hội thoại hiện tại + persistent storage cho kiến thức qua sessions.

🎯 NHỚ ĐỂ THI
LLM ≠ tự có memory. Context window (cửa sổ ngữ cảnh – phần thông tin LLM đang nhìn thấy) = short-lived state; External Store (kho lưu trữ bên ngoài để nhớ lâu dài) = persistent memory.
Session mới mặc định bắt đầu từ zero nếu hệ thống không load memory.
02 • Context Engineering

7 Context Layers + token budget (ngân sách token – lượng token được phép dùng)

7 lớp: System • Task • User • Memory • Retrieval • Tool • Policy. Khi gần token limit phải trim theo priority; slide nhấn mạnh Policy context (ngữ cảnh chính sách/an toàn) trim cuối cùng vì safety không được bỏ.

Conflict: user preference (sở thích/thiết lập của người dùng) mâu thuẫn policy constraint (ràng buộc từ chính sách) → policy thắng.

Memory budget gợi ýTỷ lệ
Short-term (bộ nhớ ngắn hạn)10%
Long-term (bộ nhớ dài hạn) facts4%
Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra)3%
Semantic (bộ nhớ tri thức theo ý nghĩa)3%

Tổng memory vượt ~20% context theo slide → context dễ nhiễu, accuracy giảm.

🎯 NHỚ ĐỂ THI
10% + 4% + 3% + 3% = 20% cho memory.
Policy thắng preference; safety context không được trim tùy tiện.
03 • 4 loại Memory

Cognitive Memory Model

Short-term (Working)Context buffer (vùng đệm giữ nội dung hiện tại); nhanh, tạm thời. Quản lý bằng buffer (vùng đệm giữ nội dung hiện tại)/summary (bản tóm tắt)/sliding window (cửa sổ trượt – giữ phần gần nhất và phần tóm tắt).
Long-term (Declarative)Redis/PostgreSQL; user preferences & facts sống qua sessions.
Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra)Nhớ trải nghiệm có thứ tự: task, trajectory, outcome, reflection.
Semantic (bộ nhớ tri thức theo ý nghĩa)Embeddings (vector biểu diễn ý nghĩa dữ liệu) + Vector DB (cơ sở dữ liệu vector để tìm kiếm tương đồng); truy hồi domain knowledge bằng similarity/top-k (lấy k kết quả phù hợp nhất).

Short-term (bộ nhớ ngắn hạn) strategies: Buffer (đơn giản nhưng dễ đầy) • Summary (ổn định nhưng tốn LLM call) • Sliding window (cửa sổ trượt – giữ phần gần nhất và phần tóm tắt) = system + summary (bản tóm tắt) + last K turns, slide xem là tradeoff tốt cho production.

🎯 NHỚ ĐỂ THI
Short-term (bộ nhớ ngắn hạn) = gần nhất • Long-term (bộ nhớ dài hạn) = facts/prefs • Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) = “đã trải qua gì” • Semantic (bộ nhớ tri thức theo ý nghĩa) = “biết gì”.
03 • Long-term (bộ nhớ dài hạn) & flow

Redis + Buffer (vùng đệm giữ nội dung hiện tại) → Summarize (tóm tắt) → Extract (trích xuất thông tin quan trọng) → Persist (lưu bền vững để dùng lại)

Buffer (vùng đệm giữ nội dung hiện tại)→Summarize (tóm tắt)→Extract (trích xuất thông tin quan trọng) facts→Persist (lưu bền vững để dùng lại)
  • Sau conversation: LLM extract (trích xuất thông tin quan trọng) key facts rồi store vào Redis.
  • Session mới: load user profile vào system prompt.
  • Ví dụ TTL (Time To Live – thời gian dữ liệu được tồn tại) trong slide: preferences 90d, facts 30d, sessions 7d.
  • Redis mapping: Hash = preferences, Set = facts, List = recent session history.
  • Chỉ persist (lưu bền vững để dùng lại) sau task completion để tránh inconsistent state (trạng thái không nhất quán).
  • Nếu long-term (bộ nhớ dài hạn) fact mâu thuẫn short-term (bộ nhớ ngắn hạn) info → recency wins (thông tin mới hơn được ưu tiên), đồng thời flag review.
🎯 NHỚ ĐỂ THI
Buffer (vùng đệm giữ nội dung hiện tại) → Summarize (tóm tắt) → Extract (trích xuất thông tin quan trọng) → Persist (lưu bền vững để dùng lại).
Không write giữa task; conflict mới–cũ: thông tin mới hơn thắng nhưng nên flag.
04 • Implementation

LangGraph Memory State + Memory Router (bộ định tuyến bộ nhớ – chọn loại memory cần truy hồi)

State trong slide gồm: messages, user_profile, episodes, semantic_hits, memory_budget.

  1. load_memory: đọc memory khi bắt đầu.
  2. Inject (đưa thông tin vào context cho LLM): đưa vào system prompt theo priority.
  3. save_memory: ghi khi kết thúc.

Priority recall: 1) short-term (bộ nhớ ngắn hạn) gần nhất → 2) long-term (bộ nhớ dài hạn) facts/user prefs → 3) relevant episodes → 4) semantic (bộ nhớ tri thức theo ý nghĩa) knowledge.

Unified interface: retrieve(query, types=["all"]) trả merged context từ cả 4 loại, sau đó trim theo token budget (ngân sách token – lượng token được phép dùng).

🎯 NHỚ ĐỂ THI
load → retrieve (truy hồi/lấy lại thông tin)/router → inject (đưa thông tin vào context cho LLM) → LLM → save.
04 • Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) & Semantic (bộ nhớ tri thức theo ý nghĩa)

Nhớ trải nghiệm vs nhớ tri thức

Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra): lưu tuple (task, trajectory, outcome, reflection). Có LRU (Least Recently Used – loại dữ liệu lâu không được dùng), importance decay (độ quan trọng giảm dần theo thời gian), consolidation (hợp nhất các trải nghiệm tương tự); có thể extract (trích xuất thông tin quan trọng) reusable strategy sang skill library kiểu Voyager.

Semantic (bộ nhớ tri thức theo ý nghĩa): domain docs → embeddings (vector biểu diễn ý nghĩa dữ liệu) → Chroma/Pinecone; query task → cosine similarity (độ tương đồng cosine giữa các vector) → top-k (lấy k kết quả phù hợp nhất) chunks. Fact mới có thể add vào DB với source, confidence (độ tin cậy), timestamp (thời điểm dữ liệu được ghi).

Phân biệt hay thi: Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) trả lời “lần trước trong task tương tự tôi đã làm gì?”; Semantic (bộ nhớ tri thức theo ý nghĩa) trả lời “domain này có kiến thức gì liên quan?”.

🎯 NHỚ ĐỂ THI
Episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) = experience trajectory • Semantic (bộ nhớ tri thức theo ý nghĩa) = knowledge retrieval.

05 • Privacy

Privacy-by-Design (thiết kế quyền riêng tư ngay từ đầu) & GDPR

  • Mặc định không lưu PII (thông tin định danh cá nhân); user phải explicit opt-in (người dùng chủ động đồng ý) trước khi agent nhớ thông tin cá nhân.
  • Right to be Forgotten (quyền yêu cầu xóa dữ liệu đã lưu): xóa mọi memory entry liên quan và confirm deletion.
  • Federated Forgetting (xóa dữ liệu ở mọi agent/store có bản sao): multi-agent phải propagate yêu cầu xóa tới mọi agent/store có copy.
  • Checklist: Data minimization (chỉ lưu dữ liệu thật sự cần thiết) • Purpose limitation (chỉ dùng dữ liệu đúng mục đích) • Storage limitation (giới hạn thời gian lưu dữ liệu)/TTL (Time To Live – thời gian dữ liệu được tồn tại) • Consent management • Deletion verification.
🎯 NHỚ ĐỂ THI
Privacy không phải afterthought — thiết kế ngay từ đầu.
06 • Trends 2025–2026

5 xu hướng cần nhớ

  1. Cross-session memory (bộ nhớ xuyên phiên – nhớ qua nhiều cuộc hội thoại): user-scoped (được tách/giới hạn theo từng người dùng) profile, open loops (các việc/vấn đề còn dang dở), episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) store.
  2. Compaction (nén context bằng cách giữ/tóm tắt phần quan trọng) + notes: giữ recent context, đẩy facts/tasks sang durable notes (ghi chú bền vững dùng lại về sau).
  3. Identity files (các file định nghĩa hành vi/nhận dạng của agent): AGENTS.md / CLAUDE.md / SOUL.md thành control plane (lớp điều khiển quy tắc và hành vi).
  4. Heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái) loops: wake-up định kỳ để refresh state, xử lý backlog, làm sạch notes.
  5. Compiled knowledge base: tích lũy wiki đã tổng hợp thay vì RAG lại raw docs mỗi lần.
🎯 NHỚ ĐỂ THI
Cross-session • Compaction (nén context bằng cách giữ/tóm tắt phần quan trọng) • Identity files (các file định nghĩa hành vi/nhận dạng của agent) • Heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái) • Compiled KB (cơ sở tri thức đã được tổng hợp và biên tập).
06 • Cross-session

Đừng mang full transcript sang session mới

Memory hiện đại ưu tiên lưu preferences, decisions, open loops (các việc/vấn đề còn dang dở), episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra) outcomes, không dump toàn bộ chat.

  • Thread-scoped (chỉ tồn tại trong một luồng hội thoại) state → user-scoped (được tách/giới hạn theo từng người dùng) memory namespace (không gian tên để tách dữ liệu).
  • Save chat history → save structured facts.
  • Similarity-only → scope + recency + relevance + provenance (nguồn gốc và lịch sử dữ liệu).
  • Write-back (ghi thông tin mới trở lại bộ nhớ) cuối phiên → hot path + background consolidation (hợp nhất các trải nghiệm tương tự).

Kiến trúc nên namespace (không gian tên để tách dữ liệu) theo user_id, org_id, topic; record có source, timestamp (thời điểm dữ liệu được ghi), confidence (độ tin cậy), ttl (Time To Live – thời gian dữ liệu được tồn tại). Gán nhầm memory sang user khác là bug nghiêm trọng.

🎯 NHỚ ĐỂ THI
Persist (lưu bền vững để dùng lại) facts, decisions, prefs, open loops (các việc/vấn đề còn dang dở) — không persist (lưu bền vững để dùng lại) raw chat vô tội vạ.
06 • Compaction (nén context bằng cách giữ/tóm tắt phần quan trọng)

Recent turns + Session summary (bản tóm tắt) + Durable notes (ghi chú bền vững dùng lại về sau)

Compaction (nén context bằng cách giữ/tóm tắt phần quan trọng) tốt hơn full transcript vì bỏ phần đã xử xong khỏi context nhưng vẫn giữ trạng thái cần thiết.

Detect pressure→Summarize (tóm tắt)→Extract (trích xuất thông tin quan trọng) notes→Rebuild context
  • Chạy khi gần token limit, session kéo dài, hoặc chuyển pha thảo luận → thực thi.
  • Summary (bản tóm tắt) phải ưu tiên state, decisions, TODO, constraints, không tóm tắt lan man.
🎯 NHỚ ĐỂ THI
Compaction (nén context bằng cách giữ/tóm tắt phần quan trọng) giữ 3 lớp: recent turns + session summary (bản tóm tắt) + durable notes (ghi chú bền vững dùng lại về sau).
06 • Identity Files (các file định nghĩa hành vi/nhận dạng của agent)

Control plane (lớp điều khiển quy tắc và hành vi), không phải retrieval engine (cơ chế truy hồi/tìm kiếm thông tin)

FileVai trò
AGENTS.mdWorkflow, boundaries, coding/execution norms
SOUL.mdIdentity, tone, preferred defaults
MEMORY.mdDurable notes (ghi chú bền vững dùng lại về sau), memory schema, recap decisions
TASKS.mdOpen loops (các việc/vấn đề còn dang dở), backlog, agenda

Không hiểu sai: các file này không tự re-rank, không TTL (Time To Live – thời gian dữ liệu được tồn tại), không conflict resolution, không provenance (nguồn gốc và lịch sử dữ liệu). Vì vậy stack tốt là instruction files + working notes + retrieval memory backend.

🎯 NHỚ ĐỂ THI
Instruction files: “cư xử thế nào?” • Retrieval memory: “nên nhớ gì lúc này?”.
06 • Heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái)

Agent có vòng đời, nhưng dễ memory poisoning (đầu độc bộ nhớ bằng thông tin/chỉ dẫn độc hại)

Heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái)/wake-up phù hợp personal assistant, inbox triage, research copilot, coding agent có backlog dài ngày. Có thể compact context, refresh task list, de-duplicate notes, expire stale tasks, tạo recap.

Rủi ro: prompt injection có thể trở thành memory/backlog poisoning (đầu độc danh sách công việc tồn đọng) kéo dài qua nhiều phiên.

  • Allowlist (danh sách loại dữ liệu/hành động được phép) memory types được phép ghi.
  • Mọi durable write có source, timestamp (thời điểm dữ liệu được ghi), confidence (độ tin cậy).
  • Tách user request / system rule / agent inference.
  • High-impact writes qua human review (con người kiểm tra/xác nhận) hoặc policy check (kiểm tra theo chính sách).
🎯 NHỚ ĐỂ THI
Heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái) không được tự tăng quyền; nó chỉ là cơ chế vận hành nền.
06 • Compiled KB (cơ sở tri thức đã được tổng hợp và biên tập)

Khi nào tốt hơn plain RAG (RAG thông thường – mỗi câu hỏi truy hồi từ tài liệu gốc)?

LLM Wiki / compiled KB (cơ sở tri thức đã được tổng hợp và biên tập): raw sources → persistent wiki (entity pages, summaries, links) + curation rules về source, contradiction, freshness.

Plain RAG (RAG thông thường – mỗi câu hỏi truy hồi từ tài liệu gốc) đủ tốt: hỏi một lần, corpus đổi liên tục, chưa cần curate theo entity/timeline/contradiction.

Nâng lên compiled KB (cơ sở tri thức đã được tổng hợp và biên tập) khi: cùng corpus bị hỏi lặp nhiều tuần; cần timeline, contradiction, decision history, entity pages và audit trail (dấu vết lịch sử để kiểm tra/đối chiếu).

🎯 NHỚ ĐỂ THI
RAG = retrieve (truy hồi/lấy lại thông tin) raw chunks • Compiled KB (cơ sở tri thức đã được tổng hợp và biên tập) = tri thức đã được chưng cất và tích lũy theo thời gian.

🧩 Công thức chọn Memory nhanh

Cần hội thoại hiện tại? → short-term (bộ nhớ ngắn hạn). Cần nhớ user qua ngày khác? → long-term (bộ nhớ dài hạn). Cần học từ task từng làm? → episodic (bộ nhớ trải nghiệm/sự kiện đã xảy ra). Cần truy hồi kiến thức domain? → semantic (bộ nhớ tri thức theo ý nghĩa). Context dài? → compaction (nén context bằng cách giữ/tóm tắt phần quan trọng). Cần hành vi/identity ổn định? → identity files (các file định nghĩa hành vi/nhận dạng của agent). Cần duy trì backlog nền? → heartbeat (vòng chạy định kỳ để agent cập nhật trạng thái) + guardrails. Cùng corpus bị hỏi phức tạp lặp lại? → cân nhắc compiled KB (cơ sở tri thức đã được tổng hợp và biên tập).

= bộ nhớ làm việc
Tương ứng short-term memory/context hiện tại.
Long-term memory
= bộ nhớ dài hạn
Facts và preferences sống qua nhiều session.
Episodic memory
= bộ nhớ trải nghiệm
Nhớ task/trajectory/outcome/reflection đã từng xảy ra.
Semantic memory
= bộ nhớ tri thức
Knowledge được truy hồi bằng embeddings/vector search.
Context engineering
= kỹ thuật quản lý context
Quyết định model được thấy gì, theo priority và budget.
Token budget
= ngân sách token
Giới hạn phân bổ token cho từng lớp context/memory.
Trim / Eviction
= cắt / loại khỏi context
Bỏ bớt nội dung khi gần giới hạn.
Sliding window
= cửa sổ trượt
Giữ system + summary + K lượt gần nhất.
Summarization
= tóm tắt
Nén lịch sử cũ thành summary.
TTL
= Time To Live
Thời gian một memory entry được giữ trước khi hết hạn.
Write-back
= ghi ngược về memory
Sau khi xử lý, lưu facts/decision/episode vào store.
Memory router
= bộ định tuyến memory
Chọn loại memory cần retrieve theo intent của query.
Recall
= gọi lại ký ức
Truy xuất memory phù hợp để đưa vào context.
LRU
= Least Recently Used
Xóa episode ít được dùng gần đây nhất.
Importance decay
= suy giảm độ quan trọng
Điểm memory giảm theo thời gian.
Consolidation
= hợp nhất ký ức
Merge các episode tương tự thành thông tin cô đọng hơn.
Embedding
= vector biểu diễn
Mã hóa nội dung để đo similarity.
Cosine similarity
= độ tương đồng cosine
Metric dùng tìm vector gần với query.
Top-k
= k kết quả đầu
Lấy k chunk/memory phù hợp nhất.
Provenance
= nguồn gốc dữ liệu
Thông tin memory đến từ đâu và có thể kiểm chứng thế nào.
Confidence
= độ tin cậy
Mức tin của một memory/fact.
Namespace
= không gian tên
Tách memory theo user_id/org_id/topic.
Cross-session memory
= bộ nhớ xuyên phiên
Memory sống từ thread/session này sang session khác.
Open loop
= việc còn dang dở
Task/decision chưa hoàn tất cần theo dõi.
Compaction
= nén context
Giữ phần cần thiết, bỏ/summary phần đã xử lý.
Durable notes
= ghi chú bền vững
Facts/tasks quan trọng được lưu ngoài transcript.
Identity file
= file nhận dạng/chỉ dẫn
AGENTS.md, SOUL.md… giúp bootstrap hành vi ở phiên mới.
Control plane
= lớp điều khiển
Quy tắc/persona/workflow cố định cách agent vận hành.
Heartbeat loop
= vòng đánh thức định kỳ
Agent chạy nền định kỳ để refresh state/backlog.
Memory poisoning
= đầu độc bộ nhớ
Instruction/fact độc hại bị lưu và ảnh hưởng nhiều phiên.
Backlog poisoning
= đầu độc danh sách việc
Task độc hại được lưu vào backlog và chạy về sau.
Allowlist
= danh sách cho phép
Chỉ các loại memory/action được phép ghi hoặc thực hiện.
High-impact write
= ghi dữ liệu tác động lớn
Write nhạy cảm cần policy check/human review.
Privacy-by-Design
= riêng tư ngay từ thiết kế
Không chờ đến cuối mới thêm privacy.
PII
= thông tin định danh cá nhân
Dữ liệu cá nhân cần consent và bảo vệ.
Opt-in
= đồng ý chủ động
User phải đồng ý trước khi lưu PII.
Right to be Forgotten
= quyền được xóa
User yêu cầu xóa toàn bộ memory liên quan.
Federated Forgetting
= xóa lan truyền đa agent
Yêu cầu xóa phải propagate tới mọi copy/store.
Data minimization
= tối thiểu hóa dữ liệu
Chỉ lưu dữ liệu thực sự cần.
Purpose limitation
= giới hạn mục đích
Dữ liệu chỉ dùng cho mục đích đã xác định.
Storage limitation
= giới hạn thời gian lưu
Không giữ dữ liệu lâu hơn cần thiết; dùng TTL.
Compiled knowledge base
= KB đã biên tập/tổng hợp
Tri thức được tích lũy, liên kết, curate qua thời gian.
Plain RAG
= RAG thông thường
Mỗi query retrieve top-k chunks từ raw corpus.
Audit trail
= dấu vết kiểm toán
Lịch sử nguồn, quyết định, thay đổi để kiểm tra lại.
Memory hit rate
= tỷ lệ truy hồi trúng
Bao nhiêu lần hệ thống lấy đúng memory cần thiết.
Token efficiency
= hiệu quả token
Mức giá trị đạt được so với lượng token sử dụng.

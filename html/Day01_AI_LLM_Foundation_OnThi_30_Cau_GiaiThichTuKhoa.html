01 · AI Taxonomy

Các tầng AI & 3 nhóm AI

AI (Artificial Intelligence – trí tuệ nhân tạo) là tầng rộng nhất. Bên trong lần lượt có ML (Machine Learning – máy học từ dữ liệu) → DL (Deep Learning – mạng neural nhiều tầng) → Generative AI (AI sinh nội dung mới) → LLM (Large Language Model – mô hình ngôn ngữ lớn).

Ba nhóm trong slide: Discriminative AI (AI phân biệt/phân loại): Input → Label; Generative AI: Prompt → Content; Agentic AI (AI tác tử biết lập kế hoạch và hành động): Goal → Plan → Action.
🎯 NHỚ ĐỂ THIAI ⊃ ML ⊃ DL ⊃ GenAI ⊃ LLM. Phân loại = Input→Label; Sinh = Prompt→Content; Agent = Goal→Plan→Action.
02 · AI Agents

Từ LLM đến Agent

Slide chia 4 mức: Level 0 – Core reasoning engine (LLM chỉ dùng kiến thức nội tại); Level 1 – Connected Solver (kết nối search/API/database/tools); Level 2 – Strategic Problem-Solver (lập kế hoạch nhiều bước và dùng nhiều công cụ); Level 3 – Collaborative AI Agents (nhiều agent chuyên biệt phối hợp).

Công thức slide: Agent = Goal (mục tiêu) + Reasoning (suy luận/lập kế hoạch) + Tools (công cụ) + Memory (bộ nhớ/trạng thái) + Action (hành động).
🎯 NHỚ ĐỂ THILLM chỉ trả lời chưa đủ thành Agent. Agent phải hướng tới mục tiêu và có khả năng hành động qua tools.
03 · LLM

LLM hoạt động theo Next-Token Prediction

LLM (Large Language Model – mô hình ngôn ngữ lớn) trong slide dựa trên Transformer (kiến trúc mạng neural dùng attention). Cơ chế sinh chính là Next-token prediction (dự đoán token tiếp theo).

LLM sinh theo kiểu autoregressive (token vừa sinh trở thành input cho bước kế tiếp). Temperature (tham số điều chỉnh độ ngẫu nhiên/sáng tạo): thấp → ổn định hơn; cao → ngẫu nhiên hơn.
🎯 NHỚ ĐỂ THILLM không tra “đáp án đúng” rồi trả lời; nó dự đoán token tiếp theo theo xác suất.
04 · Transformer

Embedding + Position → Attention → FFN

Pipeline trọng tâm: Input Tokens → Embedding + Position → Self-Attention → Feed-Forward Network × N layers → Next Token Prediction.

Embedding (vector biểu diễn nội dung/nghĩa token) cho biết token là gì nhưng không tự mang vị trí. Positional Encoding (mã hóa vị trí) bổ sung thứ tự: X = E + P. Feed-Forward Network – FFN (mạng truyền thẳng xử lý phi tuyến từng vị trí).
🎯 NHỚ ĐỂ THIEmbedding = nội dung; Position = vị trí. Cộng hai thứ rồi mới đưa vào attention.
05 · Self-Attention

Q, K, V và công thức Attention

Self-Attention (cơ chế mỗi token chú ý các token liên quan trong context) dùng ba biểu diễn: Q – Query (tôi đang tìm gì?), K – Key (tôi có đặc trưng gì để được tìm?), V – Value (thông tin thật sự được lấy nếu phù hợp).

Công thức slide: Attention(Q,K,V) = softmax(QKᵀ / √dₖ)V. QKᵀ chấm điểm → chia √dₖ để ổn định → Softmax (đổi score thành trọng số tổng bằng 1) → weighted sum với V.
🎯 NHỚ ĐỂ THIQ hỏi – K để khớp – V mang thông tin. Score → Scale → Softmax → Weighted Sum.
06 · Mask & Multi-Head

Không nhìn tương lai + nhiều góc nhìn

Masked Self-Attention (attention có mặt nạ) trong decoder-only chặn token hiện tại nhìn các token tương lai; slide dùng causal mask (mặt nạ nhân quả) bằng cách đặt score tương lai thành −∞ trước Softmax.

Multi-Head Attention (nhiều đầu attention chạy song song) cho phép các head học các kiểu quan hệ khác nhau, sau đó concat (nối các kết quả) và qua linear projection.
🎯 NHỚ ĐỂ THIMask = không gian lận nhìn tương lai. Multi-head = nhiều “góc nhìn” song song.
07 · Token

Đơn vị LLM thật sự xử lý

Token (đơn vị nhỏ mà LLM xử lý) không nhất thiết bằng một từ. Tokenization (tách text thành các subword token). Slide lưu ý tiếng Việt, code, Unicode và text có cấu trúc có thể tốn nhiều token hơn.

Token ảnh hưởng trực tiếp đến API cost (chi phí API), context window (giới hạn lượng token model xử lý trong một lần gọi), độ dài prompt và latency.
🎯 NHỚ ĐỂ THILLM đọc token/subword, không đọc “từ” theo cách con người.
08 · Training

Pre-training → SFT → Alignment

LLM được tạo theo chuỗi trong slide: Pre-training (đọc lượng dữ liệu rất lớn để học ngôn ngữ/kiến thức) → SFT (Supervised Fine-Tuning – học từ ví dụ để trả lời đúng kiểu) → RLHF/DPO (alignment – căn chỉnh theo ưu tiên con người/an toàn).
🎯 NHỚ ĐỂ THIPre-training = đọc rất nhiều; SFT = được chỉ cách trả lời; RLHF/DPO = được uốn nắn hành vi.
09 · Giới hạn LLM

Cutoff, Hallucination, Context Window

Knowledge cutoff (mốc kiến thức – model không tự biết sự kiện sau lúc training); Hallucination (trả lời tự tin nhưng sai); Context window (bộ nhớ làm việc hữu hạn trong một lần gọi).

Slide còn nhắc Lost in the Middle (thông tin nằm giữa context dài dễ bị model bỏ sót). Các giới hạn này dẫn tới nhu cầu prompt tốt, context management, RAG và tools.
🎯 NHỚ ĐỂ THICutoff = không biết mới; Hallucination = có thể bịa; Context = chỉ nhìn hữu hạn.
10 · Token Economy

Cost & Latency

Token Economy (cách token ảnh hưởng chi phí và tốc độ): chi phí dựa trên input tokens (token gửi vào) và output tokens (token model sinh ra). Slide nhấn mạnh output token thường đắt hơn input token.

Latency (độ trễ/thời gian chờ) tăng khi context dài hơn, output dài hơn hoặc model lớn hơn. Nhiều token → thường vừa chậm vừa đắt.
🎯 NHỚ ĐỂ THITối ưu cost = tối ưu prompt + context + output. Đừng nhét context vô ích.
11 · Chọn Model

Quality ↔ Latency ↔ Cost

Trade-off (đánh đổi) chính: quality (chất lượng), latency (độ trễ), cost (chi phí). Tác vụ đơn giản/batch → ưu tiên model nhỏ, nhanh, rẻ; reasoning/code/planning phức tạp → model mạnh hơn.

Closed model (model dùng qua API hosted) tiện vận hành; Open model (model mở có thể self-host) cho nhiều quyền kiểm soát và phù hợp dữ liệu riêng tư.
🎯 NHỚ ĐỂ THIBắt đầu bằng model đủ tốt và đủ rẻ; chỉ nâng model khi quality thực sự chặn use case.
12 · API Call

Request và Response

Một API call (lần chương trình gửi yêu cầu tới dịch vụ model) có request gồm model, messages (danh sách hội thoại), max_tokens (giới hạn output), temperature.

Message có role (vai trò): system / user / assistant. Response có nội dung trả lời, usage (thống kê token) và finish_reason (lý do model dừng: stop/length/tool_calls).
🎯 NHỚ ĐỂ THIRequest: model + messages + params. Response: content + usage + finish reason.
13 · Streaming

Trả kết quả dần

Streaming response (model gửi output từng phần thay vì chờ sinh xong toàn bộ) giúp người dùng thấy câu trả lời xuất hiện sớm hơn. Đây là yêu cầu của chatbot trong lab Day 1.
🎯 NHỚ ĐỂ THIStreaming cải thiện cảm giác chờ; không đồng nghĩa tổng thời gian sinh chắc chắn ngắn hơn.
14 · Vibe Coding

Idea → Prompt → Code → Test → Refine

Vibe Coding (lập trình bằng cách mô tả ý tưởng để AI sinh code rồi developer kiểm tra/chỉnh). Workflow slide: Idea → Prompt → Code → Test → Refine.

Prompt tốt cần intent (mục tiêu rõ), context (ngữ cảnh đủ) và tiêu chí đầu ra. AI sinh code nhưng developer vẫn phải review (đọc/kiểm tra) và test.
🎯 NHỚ ĐỂ THIVibe Coding tốt ≠ copy code mù quáng. Intent rõ + context đủ + review kỹ.
15 · Lab 1

So sánh model + chatbot

Lab yêu cầu gọi API thực tế, so sánh GPT-4o và GPT-4o-mini theo latency (độ trễ), cost (chi phí), quality (chất lượng); đồng thời làm chatbot có streaming và bảng so sánh kết quả.
🎯 NHỚ ĐỂ THIThi/lab: đừng chỉ gọi được API; phải biết đọc usage và so sánh quality–latency–cost.

Tự luận 1/10
Phân biệt Discriminative AI, Generative AI và Agentic AI.
Discriminative AI nhận input và dự đoán label. Generative AI nhận prompt và sinh content mới. Agentic AI nhận goal, lập plan và thực hiện action; có thể kết nối tools để hoàn thành workflow.
Tự luận 2/10
Giải thích 5 thành phần của AI Agent.
Goal là mục tiêu; Reasoning là phân tích/lập kế hoạch; Tools là công cụ ngoài; Memory lưu trạng thái/lịch sử; Action thực thi hành động. Công thức slide: Agent = Goal + Reasoning + Tools + Memory + Action.
Tự luận 3/10
Giải thích pipeline Transformer ở mức ôn thi.
Input được token hóa; token có embedding biểu diễn nội dung và positional encoding biểu diễn vị trí. Sau đó Self-Attention cho token lấy thông tin từ context, FFN xử lý phi tuyến qua nhiều layer và cuối cùng model dự đoán token tiếp theo.
Tự luận 4/10
Giải thích Q, K, V bằng cách dễ nhớ.
Q = Query: tôi đang tìm gì? K = Key: tôi có đặc trưng gì để được khớp? V = Value: thông tin thật sự được lấy. Q so với K tạo attention score; sau scale + softmax, trọng số dùng để trộn V.
Tự luận 5/10
Vì sao cần chia √dₖ và Softmax trong attention?
QKᵀ có thể tạo score lớn. Chia √dₖ giúp ổn định score; Softmax biến score thành trọng số trong khoảng 0–1 có tổng bằng 1, rồi dùng chúng để weighted sum các Value.
Tự luận 6/10
Masked Self-Attention và Multi-Head Attention là gì?
Causal mask chặn decoder nhìn token tương lai. Multi-head chạy nhiều attention head song song để học nhiều kiểu quan hệ khác nhau, sau đó concat và linear projection.
Tự luận 7/10
Token ảnh hưởng cost và latency như thế nào?
API tính dựa trên input/output tokens; context và output dài làm số token tăng. Nhiều token thường vừa tăng cost vừa tăng latency. Vì vậy cần tối ưu prompt, context và độ dài output.
Tự luận 8/10
Ba giới hạn bẩm sinh của LLM theo slide?
Knowledge cutoff: không tự biết dữ liệu mới sau training. Hallucination: có thể tự tin nhưng sai vì tối ưu xác suất token. Context window: chỉ xử lý số token hữu hạn; context dài còn có Lost in the Middle.
Tự luận 9/10
Giải phẫu một API call.
Request thường có model, messages, max_tokens, temperature. Messages có role system/user/assistant. Response có content, model thực tế, usage gồm prompt/completion/total tokens và finish_reason như stop, length, tool_calls.
Tự luận 10/10
Vibe Coding đúng cách theo slide là gì?
Workflow: Idea → Prompt → Code → Test → Refine. Developer mô tả intent rõ, cung cấp context/tiêu chí đầu ra, để AI generate code nhưng vẫn phải test, review và refine; không phụ thuộc mù quáng vào code AI.

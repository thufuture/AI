01 · Map & Compass

RAG = OFFLINE + ONLINE. OFFLINE (làm lúc chuẩn bị/index dữ liệu): Parse → Chunk → Enrich → Embed → Index. ONLINE (chạy cho mỗi query): PreRAG → Retrieve → Rerank → Augment → Generate → PostRAG.

Error Tree (cây chẩn đoán lỗi) dùng để xác định đúng tầng hỏng trước khi sửa.

🎯 NHỚ ĐỂ THI
Chẩn đoán trước, sửa sau. Không đổi model theo cảm tính.

02 · OFFLINE — Ingestion

Ingestion (quá trình chuẩn bị dữ liệu trước khi index) đặt “trần” chất lượng. Retrieval không thể tốt hơn dữ liệu đã được parse/chunk/index. Trọng tâm: chunking + enrichment + embedding + index.

🎯 NHỚ ĐỂ THI
OFFLINE trả chi phí một lần lúc index nhưng ảnh hưởng mọi query về sau.

03 · Chunking

Fixed-size (cắt kích thước cố định): 512 tokens, overlap 64. Semantic (cắt theo đổi chủ đề). Hierarchical (phân cấp): parent 2048 / child 256; match child, inject parent. Structure-aware: theo heading/table. Late chunking: embed document trước rồi pool/cắt sau. RAPTOR: cây tóm tắt đệ quy cho câu hỏi tổng hợp.

🎯 NHỚ ĐỂ THI
Default doc có cấu trúc = Hierarchical. Late = giữ global context. RAPTOR = tổng hợp xuyên đoạn.

04 · Enrichment

Contextual Embeddings (thêm câu ngữ cảnh vào chunk trước khi embed) giúp chunk rời không mất nghĩa. Pipeline: Summarization → Hypothetical Q&A → Prepend context → Metadata extract → Embed. Hypothetical Q&A nối vocab user ↔ tài liệu và chạy OFFLINE.

🎯 NHỚ ĐỂ THI
Enrichment = làm chunk dễ tìm hơn trước khi embed; chi phí one-time lúc index.

05 · MRL

Matryoshka Representation Learning (embedding có nhiều mức số chiều lồng nhau): có thể dùng prefix 64/128/256/... chiều. Dùng vector ngắn để lọc nhanh, full dimension để chính xác hơn.

🎯 NHỚ ĐỂ THI
MRL biến số chiều thành núm vặn cost/latency/quality.

06 · Hybrid + RRF

BM25 (sparse lexical search) bắt exact keyword. Dense retrieval (vector search) bắt synonym/ý nghĩa. RRF (Reciprocal Rank Fusion – gộp thứ hạng) kết hợp hai nguồn, không cần training. Tiếng Việt: BM25 cần word segmentation trước index.

🎯 NHỚ ĐỂ THI
Hybrid + RRF = baseline production: BM25 bắt exact, Dense bắt synonym.

07 · ColBERT / SPLADE / Fusion

ColBERT dùng late interaction (so khớp token-level) + MaxSim, giữ chi tiết token hiếm nhưng tốn storage multi-vector. SPLADE (learned sparse retrieval) học term expansion để đóng vocab gap. Weighted Fusion học trọng số khi có labeled data; chưa có label thì RRF.

🎯 NHỚ ĐỂ THI
Precision token-level thấp → ColBERT. Recall do vocab gap → SPLADE. Có label → Fusion.

08 · ColPali & Vector DB

ColPali (visual document retrieval) embed trực tiếp ảnh trang, phù hợp PDF/scan/bảng/layout khó parse. Chọn DB theo nhu cầu: Postgres vừa → pgvector; managed zero-ops → Pinecone; hybrid + metadata → Qdrant; quan hệ entity → Neo4j.

🎯 NHỚ ĐỂ THI
Không chọn Vector DB theo hype. Chọn theo hybrid/filter/scale/ops và loại dữ liệu.

09 · Reranking

Two-stage retrieval: Retrieve top-20 (recall rộng) → cross-encoder rerank (đọc query+doc cùng lúc) → top-3 (precision hẹp). Slide nêu khoảng +30–50ms/query đổi lấy +15–25% precision, tùy data. Tiếng Việt self-host: bge-reranker-v2-m3.

🎯 NHỚ ĐỂ THI
Retriever ưu tiên Recall; Reranker ưu tiên Precision. Rerank vô dụng nếu chunk đúng chưa được retrieve.

10 · Control Flow

HyDE (sinh hypothetical answer rồi embed để search): vocab gap. Multi-Query (tách query phức thành sub-query): câu nhiều phần/multi-hop. CRAG (Corrective RAG): grade retrieval → Correct dùng; Ambiguous rewrite; Wrong fallback. Context dư/mâu thuẫn → NLI filter/compression; cần nguồn → citation injection.

🎯 NHỚ ĐỂ THI
Mỗi vấn đề một pattern, đừng bật hết. ONLINE pattern thường tốn thêm chi phí mỗi query.

11 · RAGAS — 4 metrics

Context Recall ≥ 0.75: lấy đủ thông tin chưa? Context Precision ≥ 0.75: chunk liên quan có xếp cao không? → thấp thì sửa Retrieve/Rerank. Faithfulness ≥ 0.85: answer có bám context không? Answer Relevancy ≥ 0.80: có đúng trọng tâm không? → thấp thì sửa Generate/prompt.

🎯 NHỚ ĐỂ THI
Không dùng một điểm tổng. Tách Retrieval vs Generation để biết đúng tầng hỏng.

12 · Giới hạn Embedding

Metadata filtering sửa temporal/numerical blindness. NLI verification bắt negation/entity-swap. Failure-aware routing phát hiện lỗi rồi rewrite/decompose/refuse. Quan hệ nhiều entity → GraphRAG; high-stakes → Human-in-the-loop.

🎯 NHỚ ĐỂ THI
Không phải lỗi nào cũng fix bằng thêm data hoặc đổi embedding model.

13 · Lab 18

5 module: m1_chunking.py — semantic/hierarchical/structure-aware; m2_search.py — BM25 Vietnamese + Dense + RRF; m3_rerank.py — CrossEncoder top-20→top-3; m4_eval.py — RAGAS 4 metrics + failure analysis; m5_enrichment.py — contextual/summary/hypo-Q&A.

🎯 NHỚ ĐỂ THI
Công thức: Đo RAGAS → Error Tree → chọn đúng tầng → sửa → đo lại delta.
